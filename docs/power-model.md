# 每日菜单与续航模型

## 正常日常路径

设备默认在 07:05、11:35、18:05 三次计划唤醒，但正常网络下每天只完成一次自动联网：

1. 当天第一次尚未成功同步的计划唤醒连接 Wi-Fi，拉取一个版本的四张菜单。
2. 成功后记录当天已同步；后续餐次唤醒只从本地文件切换到当前菜单。
3. 同步失败依次安排 15、60、240 分钟重试；第 4 次后停止额外重试。
4. 跨日、冷启动或时间无效时按当天尚未同步处理。
5. 兜底周期默认 1440 分钟，只在唤醒表或时间不可用时参与下一次唤醒计算。

App 根据家庭餐次时间和提前量整表下发唤醒槽位。固件出厂默认值只是首次配置前的回落，
不作为 App 业务常量。SSID、加密密码、manifest URL、设备 ID、设备 Token 和唤醒配置保存在
NVS，深睡和正常升级不会丢失。

## 用户主动操作

以下操作不受“每天自动成功联网一次”限制：

- FN 唤醒后通过 BLE 执行 `SYNC_NOW`。
- 设备醒着时长按 PREV 立即同步。
- 设备醒着时长按 NEXT 请求重新生成后同步。
- App 通过 BLE 配置、查询、直传或触发当前画面。

PREV/NEXT 从深睡唤醒时只轮播本地菜单，不自动打开 BLE 或联网。FN 短按打开 60 秒 BLE
窗口，长按延长为 180 秒；BLE 连接期间保持唤醒。

## 功耗判断

需要区分三个指标：

| 指标 | 正常值 | 说明 |
| --- | --- | --- |
| 计划唤醒 | 3 次/日 | 早餐、午餐、晚餐前各一次 |
| 自动成功联网 | 1 次/日 | 后续餐次使用本地缓存 |
| 电子纸刷新 | 取决于画面变化 | 同图跳过；餐次切换或新版本才刷新 |

一次完整同步包含 Wi-Fi、TLS、manifest、最多 `4 x 209120` 字节下载和一次电子纸刷新。
真实耗电仍取决于信号质量、重试次数、画面变化、电池状态和面板 BUSY 时间。

当前不能仅凭唤醒次数承诺续航天数。最终数据需要在现有真机联调环境中连续记录至少 72 小时，
并用电流仪表积分或可重复电量曲线测量。

## 真机验收

- BLE `0x49` 回读三个槽位及 `1440` 分钟兜底，`0x4B` 回读 `86400` 秒轮询周期。
- 连续记录启动原因、联网尝试、成功同步、下载字节、刷新次数和深睡进入时间。
- 覆盖正常网络、弱信号、断网后恢复、manifest 无新版本、15/60/240 重试和跨日。
- 验证 BLE 连接期间不睡眠，断开或窗口结束后恢复深睡。
- 记录至少 10 次完整刷新各阶段中位数和最大值，再判断是否需要厂商快速 LUT。
